# Reader native TTS PR verification

The `native-tts` scope of `reader-private-verify.yml` runs the original private PR contract on seven standard public runners: Linux x64/arm64 CPU, macOS x64/arm64 CPU, Windows x64/arm64 CPU, and macOS arm64 Metal. Each job runs platform/runtime and package/negative archive controls, builds the pinned native runtime on the matching host, and executes its CLI help. The 45 minute budget, Node 24.22.0, pnpm 11.5.2 and Python 3.12 are preserved. It does not download models or qualify inference, devices or performance. The private manual workflow remains available separately.

The existing default-main scheduler dispatches its approved full execution ref. That pinned full resolve broker discovers this separate native scope only when the exact tested private source opts in via `release/native-tts-ci.json` and its immutable base/merge tree diff matches the original native paths or migration controls. It does not require merging or publishing public main. The broker does not dispatch unconfigured legacy sources. The migrated private checker still requires native verification for relevant changes even if the routing config is deleted, so deleting the config cannot qualify. Incomplete tree information conservatively requires the native run; the read-only private checker independently enforces the same requirement. Manual native dispatch always runs all seven hosts. Status fingerprints deduplicate failures as well as successes; explicit dispatch is needed to retry the same input.

The full and CPU contracts are unchanged. Native resolution and reporting use the existing protected broker environment and personal token; native execution jobs receive only the existing read-only source checkout key, with credentials not persisted. Runner labels and commands come from reviewed executor code, never source inputs. Source and executor contract mirrors must match byte for byte.

The native status checks run/attempt, reviewed executor SHA, exact private merge parents, current head/base/latest pending status, unique successful collector and seven actual completed successful jobs. Each closed platform receipt records actual host identity, all seven stages, build/summary hashes, and encrypted diagnostic hash. Missing, duplicate, skipped, cancelled, stale, malformed or foreign receipts cannot pass. The private read-only checker additionally downloads the aggregate artifact by digest and rechecks current evidence; it does not enforce GitHub branch protection.

Native diagnostics have their own RSA-OAEP-SHA256/AES-256-GCM recipient in `reader-native-tts-logs-public.pem`, separate from full/CPU/Hear. The owner's private key is outside Git in the persistent diagnostics-key directory; the `active-reader-native-tts.json` index identifies it without requiring key disclosure. A local synthetic CLI recovery check precedes rollout; each qualification must also recover real remote encrypted evidence. Independent backup is not yet verified.

Only the encrypted bundle and bounded receipts are uploaded for seven days. Decrypt locally with `node ci/decrypt-log.mjs <envelope> <private-key-path> <new-output>`; gunzip the output as a JSON object. Its fixed members are `private-build.log`, `private-summary.json`, and `reader-tts-build.json`, each base64 encoded with a SHA-256. The bundle excludes source trees, caches, environment dumps, model weights and user data. Build JSON and private logs are never uploaded as plaintext. Do not publish decrypted diagnostics.

Windows checkout uses an owner-only ACL on the actual job temp directory, with an actual Node child-file ACL probe before any credential is introduced. Inherited ACL tightening can propagate to existing unprotected children in this disposable job directory. The original directory ACL is restored after checkout, with an existing synthetic child used to verify restoration. Checkout key files disable inheritance and remain protected; reserved RUNNER_TEMP is not overridden. If backup persistence or the pre-key probe fails, the in-memory original descriptor is used to roll back immediately. This addresses the ARM image default temp ACL rejected by system OpenSSH; strict host and key checks and the existing read-only key remain unchanged. The original failed run is retained.
